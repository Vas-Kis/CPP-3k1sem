# CrossApp
 Наскрізний проєкт з крос-платформного програмування.
 Предметна область: Склад. Сутності: Product (товар), StockBatch (партія), Warehouse (склад), Movement (переміщення). 
 

 ## Запуск
 dotnet build
 dotnet run --project src/Cli
 ## Середовище
 .NET SDK 10.0, Windows 11 x64

 ## Додаткове завдання:
 У каталозі publish для RID linux-x64 78,77 МБ
 У каталозі publish для RID win-x64 76,62 МБ 

 ## Різниця self-contained vs framework-dependent:
 Framework-dependent публікація: лише код і залежності, без runtime.
 Self-contained публікація: каталог великий і прив’язаний до RID.


| RID | Режим | Розмір publish | Потрібен runtime |
| :--- | :---: | :---: | :---: |
| win-x64 | self-contained | 153,71 | ні |
| win-x64 | framework-dependent | 0,39 | так (.NET 10) |
| linux-x64 | self-contained | 157,58 | ні |

## Інваріанти:
* Обов'язкова присутність ідентифікатора
* SKU не може бути порожнім
* Назва не може бути порожньою
* Початковий залишок не може бути від'ємним
* SKU товару має бути унікальним у межах одного складу

Метод `Product.FromImportResult` перетворює коректні DTO на сутності `Product`,
зберігає помилки імпорту та додає помилки інваріантів із номерами рядків.

`Warehouse.AddProduct` перевіряє унікальність SKU у парі «склад — товар» і повідомляє
значення SKU та ідентифікатор складу при порушенні.

`Order` починається у стані `Draft`. Дозволені переходи: `Draft → Confirmed`,
`Draft → Cancelled` і `Confirmed → Cancelled`; решта переходів відхиляється.

Перевірки, що стосуються однієї сутності (наприклад, невід'ємний залишок товару),
залишаються в ній. Перевірка унікальності SKU потребує знання інших товарів того
самого складу, тому в цьому прикладі вона виконується при додаванні товару до `Warehouse`.

## Лабораторна робота 5: сервісний шар

Контракт `ICatalogStore` у Core має дві реалізації: `InMemoryCatalogStore` для
тимчасових даних і `FileCatalogStore` для збереження каталогу у JSON.
`CatalogService` залежить лише від `ICatalogStore` та надає операції додавання,
приходу, видачі, перегляду і пошуку товарів. Конкретне сховище створюється в
`src/Cli/StoreFactory.cs`; контейнер DI не використовується.

```powershell
dotnet run --project src/Cli -f net10.0 -- demo-events
dotnet run --project src/Cli -f net10.0 -- demo-events --file
```

Без `--file` використовуються початкові дані в пам'яті, які не зберігаються
між запусками. З `--file` каталог читається при першому зверненні та
зберігається після кожної зміни у `data/catalog.json` відносно каталогу
запущеного застосунку (`AppContext.BaseDirectory`); наступний запуск побачить
попередні записи. Команда `demo-events` також демонструє відмову для неіснуючого ID.
Призначення: облік залишків товарів по партіях.

## Лабораторна робота 7: звіти через LINQ

Запити розміщені в `src/Core/Reports/ReportService.cs`: приймають `IEnumerable<Product>`
і не залежать ні від сховища, ні від консолі. `src/Cli/Program.cs` лише викликає їх
і виводить результат.

| Команда | Що показує |
| :--- | :--- |
| `report-top` (типова) | топ-5 товарів за залишком |
| `report-low` | товари із залишком менше 10 |
| `report-groups` | кількість позицій і сумарний залишок за одиницею виміру |
| `report-sum` | кількість позицій, сума, середній і максимальний залишок |
| `demo-deferred` | демо відкладеного виконання |
| `demo-events` | демо подій каталогу (лабораторна робота 6) |

```powershell
dotnet run --project src/Cli -f net10.0 -- report-groups
dotnet run --project src/Cli -f net10.0 -- report-sum --file
```

### Відкладене виконання

Виклик `source.Where(p => p.Quantity < 10)` у `src/Cli/DeferredExecutionDemo.cs` лише
описує запит; список перебирається під час кожного виклику `Count()` і під час `ToList()`.
Перший `Count()` дав 3, а другий - 4, бо між ними до `source` додано товар SKU-999 із
залишком 3, і другий виклик заново перебрав уже змінене джерело. `ToList()` зафіксував
4 елементи в окремому списку, тому після `source.Clear()` `snapshot.Count` так само
дорівнює 4. Методи `ReportService` завершуються `ToList()` або агрегатами, тому їхні
запити виконуються один раз, ще до повернення результату.
